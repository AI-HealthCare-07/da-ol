1. 매주 리뷰어를 한명씩 지정해서 그 주에는 그 사람한테만 리뷰를 요청하는 식으로 진행

**프론트엔드 (설아님, 재경님)**

- 이번 주 기획 문서
- 사용자 시나리오 2~3개 쓰기 (설아님)
전체 화면 목록 만들기: 로그인·회원가입, 추가 정보 입력, 홈(오늘의 복약), 처방 등록(사진 올리기), 인식 결과 확인, 내 약 목록, 약 상세, 복약 기록 캘린더, 가이드 보기, 챗봇 창, 진료 준비, 마이페이지(내 정보·건강 프로필·생활 일과·알림 설정)
화면 이동 흐름 그리기: 어느 화면에서 무엇을 누르면 어디로 가는지
와이어프레임 그리기: 화면마다 버튼, 입력칸, 안내 문구의 위치. 예외 상황 화면(인식 실패, 가이드 만드는 중, 확인 필요 표시)도 포함해요.
화면별 필요한 API 체크: "이 화면은 내 약 목록 조회, 복용 체크 API가 필요하다"처럼 적어서 백엔드에 넘겨요.
- 화면을 반으로 나눈다면, 설아님은 처방 등록·확인 화면·오늘의 복약·내 약·진료 준비를, 다른 한 분은 회원·마이페이지·가이드·챗봇·복약 기록을 맡는 식이에요.
- 다음 주부터 개발
- 프레임워크 정하고 프로젝트 세팅 (React 등은 팀 결정 사항)
화면 만들기: 모바일(360px)부터 데스크톱까지 깨지지 않게 반응형으로
API 연결하기: 로그인 토큰 처리, 사진 업로드, 가이드 진행 상태 표시, 챗봇 답변 실시간 표시
접근성: 중장년층 사용자를 고려한 큰 글씨와 큰 버튼
