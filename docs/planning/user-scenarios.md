# 다올 사용자 시나리오

2026-11-20 · 김설아 (11/19 수정본을 1차 축소안 기준으로 다시 정리)

요구사항 정의서 **1차 축소안(11/20)** 기준으로, 대표 타겟에 맞춘 가상 회원 2명이 다올을 쓰는 흐름을 정리했습니다. 시나리오 1은 데모데이 1차 시연 흐름, 시나리오 2는 2차 기능으로 맞춤 시간표·기록을 넓히는 흐름, 시나리오 3은 3차 기능(알림·파트너·꾸미기·부가 기능)까지 붙은 장기 사용 흐름입니다. 2·3차 요구사항이 어느 시나리오에 들어 있는지는 맨 아래 '요구사항별 시나리오'에 정리했습니다.

- **대표 타겟**: 고혈압·당뇨·이상지질혈증 등 만성질환으로 여러 먹는 약을 오래 복용하는 중장년·고령 환자. 시스템은 먹는 약을 복용하는 누구나 쓸 수 있게 설계합니다.
- **범위**: 먹는 약만 다룹니다. 주사·기타 약, 퇴원요약지, 감량 일정, 냉장 보관 안내는 제외했습니다. (11/19)
- **1차 축소안(11/20)**: 생활 일과 입력, 병용 주의(DUR), 검증 재생성은 2차입니다. 1차 시간표는 기본 일과(기상 07:00 / 식사 08:00·12:30·18:30 / 취침 23:00)로 계산합니다. 직접 입력(MED-001)은 범위를 줄여 1차에 둡니다.
- **쓰는 곳**: 와이어프레임(wireframe.md), API 명세서(api-spec.md), 배포 전 검수 시나리오(REQ-NFR-011)와 공용 테스트 처방의 출발점
- **표 읽는 법**: 단계마다 회원 행동, 시스템 동작, 보이는 화면(와이어프레임 번호), 관련 요구사항 ID를 적었어요. '확인 포인트'는 그대로 테스트 케이스로 쓸 수 있어요.
- **구현 단계**: 요구사항 옆 (2차)·(3차) 표시가 없으면 1차예요.
- **약을 등록하는 사람**: 약은 복용하는 사람 본인 계정에 등록해요. 보호자는 가입과 등록을 옆에서 돕는 역할이에요. (가족 프로필은 이번 범위에서 제외)

※ 약품명·처방 내용은 설명을 위한 가상 예시이며, 실제 의학적 판단이 아닙니다.

## 시나리오 1. 처방전 한 장으로 시작해 첫 꽃을 피우기 (1차 시연 흐름)

**가상 회원 A** · 66세 여성, 고혈압·이상지질혈증. 동네 내과에서 혈압약과 고지혈증약을 한 달씩 처방받아 먹어요. 스마트폰은 메신저 정도만 쓰고, 처음 가입은 딸이 옆에서 도와줘요. 1차에서는 생활 일과를 입력하지 않으므로 기본 일과로 시간표가 계산돼요.

**예외 흐름 (1차)**

1. 사진이 흐려서 글자를 못 읽으면 '다시 찍기 / 직접 입력하기' 버튼을 보여줘요. 직접 입력은 약 이름 검색(상품명·성분명)으로 고르고, 1회 용량·1일 횟수·총 일수를 숫자로 넣고, 복용 조건은 식전 n분 / 식후 n분 / 취침 전 / 필요시 중에서 골라요. 등록하면 홈으로 돌아와요. (OCR-002, MED-001)
2. 처방전 문구가 규칙으로 바뀌지 않으면(예: '통증시') '복용 조건 확인 필요'로 두고 회원이 목록에서 골라요. (MED-008)
3. 1일 1·2회인데 끼니가 안 적혀 있으면 임의로 시간을 정하지 않고 '복용 시간 확인 필요'로 두고, 회원이 아침·점심·저녁 중에서 골라요. (MED-009)
4. 약 이름이 정확히 맞지 않으면 비슷한 약 상위 3개 중에서 고르게 하고, 고르지 않으면 다른 약 정보를 대신 연결하지 않아요. 끝내 없으면 '이 약은 안내 정보가 없습니다'를 보여줘요. (OCR-005)
5. 처방전에 연고·파스 같은 줄이 섞여 있으면 회색으로 '먹는 약만 등록할 수 있어요'를 보여주고 저장하지 않아요. 잘못 분류됐으면 '먹는 약이에요'로 되돌려요. (OCR-004)
6. 같은 약이 두 번 읽히면 '같은 약이 두 번 읽혔어요. 하나로 합칠까요?'라고 묻고, 자동으로 합치지 않아요. (OCR-004)
7. 가이드 검증에 걸린 항목은 공공데이터 기본 정보로 대신 보여주고 '확인이 필요해요'를 표시해요. AI가 응답하지 않거나 30초 안에 끝나지 않으면 기본 약 정보와 '다시 시도' 버튼을 보여줘요. (VERI-005 1차 범위, GUIDE-007)
8. 저녁 칸을 체크하지 못하고 하루가 끝나면 꽃이 피지 않아요. 시들거나 죽는 연출은 쓰지 않아요. (MED-017, NFR-018)
9. 챗봇 답변이 실패하면 '다시 보내기' 버튼을 보여주고 사용 횟수에서 차감하지 않아요. (CHAT-001)

**확인 포인트**

- [ ] '확인하고 저장'을 누르기 전에는 처방이 저장되지 않고 시간표도 계산되지 않음
- [ ] 저장하면 홈으로 이동하고, 약통 칸과 가이드 생성 안내가 바로 보임
- [ ] 처음 등록한 날은 등록 시각 이전 회차가 '시간 지남'으로 기록되지 않음
- [ ] 검증을 통과하기 전의 가이드는 화면에 나오지 않음
- [ ] 가이드의 용량·횟수·일수·복용 시각이 확정 처방과 같음
- [ ] 가이드에 처방에 없는 약 0건, 복용 중단·용량 변경 권유 0건, 면책 문구 누락 0건
- [ ] 처방 확정 후 원본 사진이 삭제됨 (확정 안 하면 3시간 뒤 자동 삭제)
- [ ] 약통 칸 수가 그날 복용 회차 수와 같음 (필요시 약은 제외)
- [ ] 하루 칸을 모두 닫았을 때만 꽃이 피고, 체크를 취소하면 꽃도 취소됨
- [ ] 응급 안내가 AI 답변보다 먼저 나오고, 처방 변경 질문에는 답하지 않음
- [ ] 다른 회원의 처방·가이드 주소로 접근하면 404

## 시나리오 2. 약이 늘어난 직장인의 맞춤 시간표와 화단 (2차 차별점)

**가상 회원 B** · 54세 남성, 당뇨·이상지질혈증. 회사에 다니며 평일에는 07:00에 일어나 아침을 거르고, 12:30 점심, 19:30 저녁, 00:30에 자요. 주말에는 09:00에 일어나 세 끼를 다 먹어요. 원래 이상지질혈증약(1일 1회 취침 전, 30일)을 먹고 있었는데, 이번에 당뇨약(1일 3회 식후 30분, 30일)이 새로 추가됐어요. 가입은 마쳤어요.

> 1차에서는 이 회원도 기본 일과로 계산되고, 4단계(등록 시각 이후 회차부터)만 1차로 동작해요. 나머지는 2차 기능이 붙은 뒤의 흐름이에요.
