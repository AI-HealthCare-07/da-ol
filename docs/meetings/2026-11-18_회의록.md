## 3. 논의 내용

### 안건 1. 업로드 장 수와 용량

- 처방전·약봉투 '1회 1장'은 약이 많아 처방전이 2장 이상인 경우 등록할 방법이 없다는 의견이 나옴
- 장 수 대신 용량으로 제한하기로 함: 파일 1개당 10MB, 합계 30MB (CLOVA OCR 파일 한도 50MB 안)
- 한 번 업로드는 처방 한 건으로 보고, 병원명·처방일이 다르면 따로 등록하도록 안내. 다른 병원 처방전은 따로, 약봉투는 한 장만 찍어도 됨
- P-49의 'PDF 1페이지 제한'은 충돌해서 빼고, 약국 영수증 같은 페이지가 섞이는 문제는 중복 표시와 병원명·처방일 확인으로 대응
- '이 페이지 제외' 기능은 영수증에서는 약이 거의 매칭되지 않고 잘못 들어간 행은 표에서 지울 수 있어 보류
- 남은 확인: 장 수 상한이 없어졌는데 CLOVA OCR은 PDF 1회 호출에 최대 10페이지까지라, 별도 상한이 필요한지 백엔드 확인 필요

### 안건 2. 1차가 2차에 기대는 곳

- A: 1차 화면의 '진료 준비에 추가' 버튼은 넣을 곳(MED-015)이 2차라 1차에서는 숨김
- B: 재생성 실패 시 '확인 필요' 표시는 1차 시연에 필요해서 화면 표시만 1차로 올림
- C: 원문 대조 검증을 하려면 출력 템플릿 고정이 1차부터 필요. 1차에서도 가볍게 일관성을 확인하기로 함 (5번 생성 중 4번 이상 동일)
- D: 퇴원요약지 인식은 2차라 1차 검수에서 테스트 불가

### 안건 3. OCR 처리와 개인정보

- 원본 같이 보기: OCR이 약 이름·숫자를 잘못 읽을 수 있어, 사용자가 표와 원본을 바로 대조하도록 함. PDF 뷰어 대신 이미 변환한 페이지 이미지를 사용
- 미확정 보관 24시간이 너무 길다는 의견 → 3시간으로 단축. 보관 시간은 설정 값(환경 변수)으로 관리
- 로그아웃 때 미확정 건을 지우는 안도 나왔으나, 토큰 만료는 서버가 알 수 없어 시간 기준 삭제가 어차피 필요. 로그인 유지 기간과는 분리
- 마스킹: LLM에 보내는 글자는 입력 경로와 관계없이 같은 방식으로 가림. 가이드에 필요 없는 이름·면허번호·연락처도 포함
- 처방 이력: 확정한 처방 정보는 DB에 남고 '내 약' 페이지 '복용 종료' 탭(MED-002)에서 볼 수 있음. 처방 한 건 단위로 묶어 보는 화면은 2차 검토

### 안건 4. 팀 운영 방식

- 목요일은 데일리 스크럼만 짧게, 금요일 정기 회의에서 각자 만든 결과물을 함께 검토
- 멘토링 질문은 팀장이 한 번에 모아 사전 보고에 반영
- PR 리뷰는 파트별로 맡음
