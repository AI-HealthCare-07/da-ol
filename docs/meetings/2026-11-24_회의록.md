## 3. 논의 내용

### 안건 1. 이번 주 작업 범위

- 처음 잡은 계획은 마감만 적혀 있어서 할 일이 적었습니다. 각자 맡은 1차 API를 이번 주부터 시작하도록 다시 나눴습니다.
- 금요일까지 1차 API를 명세의 응답 예시만 돌려주는 가짜 버전으로 먼저 올립니다.(프론트가 다음 주에 화면을 바로 붙여 볼 수 있게 하기 위해) 형식은 민정님 공통 구조가 나온 이후 맞춥니다.
- 민정님 목·금 일이 가장 많아서, 밀리면 `POST /users/me/profile`을 다음 주로 넘깁니다.
- 재경님은 시드 스크립트를 마친 뒤 백엔드 작업에 붙습니다. 민정님 담당인 `PATCH /intakes/{intake_id}`(복용 체크·취소, 꽃 피우기)를 넘겨받는 안을 추천했습니다.
- API 키 관리 규칙
  - 키는 레포에 올리지 않고 각자 `.env`에만 넣습니다. 레포에는 값을 비운 `.env.example`만 올립니다.
  - 키 값은 디스코드 공개 채널이 아니라 개인 메시지로 전달합니다. 레포가 public이라 실수로 커밋되면 바로 노출됩니다.
  - 서버 키는 민정님이 EC2 `.env`에 넣습니다.


### 안건 2. 테스트 처방 시나리오와 drugs 데이터

- 테스트 처방 시나리오는 총 13건입니다.
  - 채민님 피드백: `parsed_by`를 `"rule"`로 통일, 예시 `drug_id` 안내, `GET /scans` 기대값과 전체 `raw_text` 추가
  - 확장 케이스 3건 추가: Case 11 약봉투, Case 12 개인정보 마스킹, Case 13 먹는 약이 아닌 약 거절. Case 11 약봉투 이미지도 새로 만들었습니다.
  - 유정님 피드백: Case 05(모사프리드정 5mg), Case 10(트라젠타정 5mg, 아토르바스타틴정 10mg)의 기대값을 `match.status: "candidates"`로 적었습니다.
- drugs 데이터
  - 테스트 처방에 있는 전문의약품은 e약은요에 없어서 허가 상세정보로 채웁니다. 성분명과 먹는 약 판단도 허가 상세정보를 씁니다.
  - 문서 종류 값은 `pill_bag`을 `pill_envelope`으로 맞춥니다 (#24).
  - 목요일 적재 전에 #25(약 이름 괄호 처리)와 #27(drugs 칸 길이 초과)이 반영돼야 합니다.
